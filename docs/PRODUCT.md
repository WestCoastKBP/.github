# Product direction

**KBP AI is being built as one workspace for your AI and tools.**

The recurring problem is fragmented work. A request arrives in one app, supporting context lives elsewhere, and the next action disappears when the conversation ends. KBP AI is intended to keep that work connected until the expected result is confirmed.

## The experience we are working toward

Describe the outcome you need. Bring in the relevant context from the tools you connect. Let an agent organize the next actions within clear permissions. See what has happened and what still needs attention.

For example: a request arrives, a response is reviewed and sent, an expected reply is tracked, and an appointment is recorded after confirmation. This is a target experience; support for each channel and action must be demonstrated separately.

## Product principles

- A visible task with its context, next action and completion criteria.
- Explicit access to tools and data.
- Approval before consequential actions when required.
- Progress based on observed events and checked results.
- Continuity when the model or assistant changes.

## Interface and integration direction

The main surface is a web application designed for iPhone and iPad use. Connected tools should serve the task without requiring the user to manage the underlying infrastructure.

Our current integration priorities are OpenAI, GitHub and Google. Supported MCP integrations are part of the technical direction. This does not mean every service, client or subscription is supported today. Authentication, account requirements, available actions and billing need to be documented for each integration.

See the [project status](STATUS.md) for what is available publicly and what must be verified before release.
